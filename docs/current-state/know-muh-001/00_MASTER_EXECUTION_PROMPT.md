Bala dependencies after `VEDA-MUH-R1`. Promote only passage-supported claim
families; retain unverified Tarabala/Chandrabala formulas as research
candidates.

- Preserve `VEDA-MUH-R1` as implemented/frozen and keep activation inactive.
- Do not implement recommendations, scoring, ranking, or automatic windows.
- Do not implement Tarabala, Chandrabala, Rahu Kalam, Yamaganda, Gulika,
  Abhijit or Durmuhurta.
- Do not start Prashna, P032, LANG-002+, D20 remediation or a new RAG store.
- No autonomous Approved Core promotion.

1. Audit existing Muhurta foundation and governance first.
2. Inspect primary classical passages, especially Bṛhat Saṃhitā Chapters 97–99

   translation uncertainty and do not treat snippets as verified formulas.
4. Classify each claim as validated, research candidate, reference-only,
   rejected or platform evidence.
5. Compare claims with the inactive runtime and preserve source/implementation
   separation.
6. Add only governance metadata and focused tests for scoped claims.
7. Synchronize roadmap, current state, changelog and acceptance records.
8. Independently review, selectively stage, commit, push and tag.
