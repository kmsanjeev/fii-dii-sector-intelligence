# VEDA-RAG-GEN-001-R Deterministic Artifact Governance

## Source of truth

Authoritative knowledge remains in the tracked platform corpus, approved-core documents, reviewed knowledge, capability records, and governed VEDA research sources, claims, passages, approvals, and rules.

`veda_unified_documents.jsonl`, `veda_unified_metadata.csv`, and `veda_unified_manifest.json` are tracked reproducible snapshots. The BM25 pickle is a rebuildable derived cache and is ignored by Git.

## Deterministic rebuild

Run:

```text
py -3.11 scripts/rebuild_unified_rag.py
```

The builder sorts records by stable document ID, renders deterministic JSONL/CSV, omits build-time timestamps from the manifest, and records authoritative-input and corpus-content hashes. It writes each artifact only when its generated bytes differ.

The manifest describes corpus version, input counts, document count, Approved-Core count, hashes, duplicate state, and missing-field state. Source retrieval, approval, promotion, and version timestamps remain inside their governed source records; they are not replaced by a rebuild timestamp.

## BM25 policy

The unified BM25 index is generated from the tracked unified documents and is therefore cache-only. Deleting it and running the rebuild command reconstructs a queryable index. It is intentionally excluded from Git tracking.

## Validation policy

Identical inputs must produce byte-identical documents, metadata, and manifest content. Adding an Approved-Core record must change the snapshots and hashes. A later rebuild with unchanged inputs must leave tracked artifacts clean.
